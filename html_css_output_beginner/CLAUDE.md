# 初級アウトプット課題 コーディングルール

## 目的・適用範囲

この `CLAUDE.md` があるディレクトリと、その配下の HTML / CSS に適用する。

- メインビジュアルと自己紹介の2セクションを正しく再現する
- 基本的な HTML / CSS のコーディング規約を守る
- 課題固有の仕様を最優先する

## 優先順位

1. 課題固有の仕様
2. 既存コードの構造・意図
3. このファイルのルール
4. 一般的な HTML / CSS のベストプラクティス

競合する場合は上位を優先する。

## 課題固有の仕様

| 項目             | 仕様                             |
| ---------------- | -------------------------------- |
| 対象セクション   | メインビジュアル・自己紹介       |

## HTMLルール

| 項目               | ルール                         |
| ------------------ | ------------------------------ |
| タグ名・属性名     | 半角小文字                     |
| 属性値             | 基本的に小文字                 |
| 属性値の引用符     | ダブルクォート `"`             |
| 文字コード         | UTF-8                          |
| `img`              | 必ず `alt` を指定              |
| インラインスタイル | 原則使用しない                 |
| 要素選択           | 見た目ではなく意味・役割で選ぶ |

### `alt`

- 意味のある画像
  - 内容が伝わる文章を指定
- 装飾目的の画像
  - `alt=""` を指定

### 要素の使い分け

| 用途   | 要素       |
| ------ | ---------- |
| リンク | `a`        |
| 見出し | `h1`〜`h6` |
| 段落   | `p`        |
| 画像   | `img`      |

`div` / `span` で、本来別の意味を持つ要素を不必要に代用しない。

### HTMLとCSSの責務

- HTML
  - 構造を記述
- CSS
  - 見た目を記述
- HTML内の `style=""`
  - 原則使用しない

```html
<!-- NG -->
<img src="Profile.PNG" alt="プロフィール画像" />
<div onclick="location.href='/profile'">プロフィールへ</div>

<!-- OK -->
<img src="profile.png" alt="プロフィール画像" />
<a href="/profile">プロフィールへ</a>
<p class="profile-text">自己紹介文です。</p>
```

HTMLでは `<meta charset="utf-8">` を指定する。

## HTML / CSS 共通ルール

| 項目       | ルール          |
| ---------- | --------------- |
| インデント | 半角スペース2つ |
| タブ文字   | 使用しない      |
| 行末空白   | 残さない        |

## CSSルール

| 項目          | ルール               |
| ------------- | -------------------- |
| `{` の前      | 半角スペース1つ      |
| コロン前      | スペースなし         |
| コロン後      | 半角スペース1つ      |
| 宣言末尾      | セミコロンを付ける   |
| CSS内の文字列 | 原則シングルクォート |
| 複数セレクタ  | 1つずつ改行          |
| CSSルール間   | 空行を1行入れる      |

```css
/* NG */
.card {
  color: #333;
  padding: 16px;
}

/* OK */
.card {
  color: #333;
  padding: 16px;
}

h1,
h2,
h3 {
  font-weight: normal;
}
```

### クラス名

見た目ではなく、役割・内容が分かる名前にする。

| 避ける               | 推奨                 |
| -------------------- | -------------------- |
| 色・サイズだけの名前 | 役割・内容を表す名前 |
| キャメルケース       | ハイフン区切り       |
| アンダースコア       | ハイフン区切り       |

```css
/* NG */
.text_gray14 {
}
.bigImage {
}

/* OK */
.profile-text {
}
.hero-image {
}
```

### 数値表記

| 条件        | NG    | OK   |
| ----------- | ----- | ---- |
| 値が `0`    | `0px` | `0`  |
| 1未満の小数 | `0.8` | `.8` |

## 実装時のルール

課題仕様を満たすための最小限の変更を行う。

- 既存コード
  - 正常なコードを理由なく変更しない
  - 不要なリファクタリングをしない
- 仕様
  - 課題にない必須仕様を勝手に追加しない
  - 任意課題は必須扱いしない
- 責務
  - HTMLは構造、CSSは見た目に分離する

## 優先しなくてよいもの

今回の課題では、以下より課題仕様の再現を優先する。

- TODOコメントの厳密な書式
- HTMLタグの省略記法
- CSSプロパティのアルファベット順
- 大規模開発向けの細かな命名規則
- 過度な抽象化・コンポーネント化
