# 初級アウトプット課題 コーディングルール解説（詳細版）

Google HTML/CSS Style Guide（Qiita翻訳版）の中から、今回の模写コーディング課題で
押さえておきたい基本ルールを、初心者向けに具体例つきで解説したメモです。

## 課題固有の仕様（必須）

コンテンツ幅は960px、横のパディングは4%です。メインビジュアルだけは全幅・高さ600px固定にします。
自己紹介は画像をCSSで丸く切り抜き、画像とテキストを横並び中央寄せで配置します。
プロフィール画像は両端そろえの横並びにします。
ブレークポイントは600pxで、スマホ表示では自己紹介・プロフィール画像とも縦積みにします。

## HTMLは小文字で書く

HTMLのタグ名・属性名・属性値は基本的にすべて半角小文字で統一します。
大文字と小文字が混在すると読みにくくなったり、表記ゆれが起きたりするためです。

```html
<!-- 避けたい例 -->
<IMG SRC="Profile.PNG" ALT="プロフィール画像">

<!-- 良い例 -->
<img src="profile.png" alt="プロフィール画像">
```

## 属性値はダブルクォートで囲む

HTMLの属性値（src="..."やclass="..."など）は、シングルクォートではなくダブルクォートで統一します。
多くのエディタの自動整形もダブルクォートを標準にしていることが多いので、それに合わせると安心です。

```html
<!-- 避けたい例 -->
<a class='btn btn-primary'>送信</a>

<!-- 良い例 -->
<a class="btn btn-primary">送信</a>
```

CSSの中で文字列を書くとき（font-familyの値など）は逆にシングルクォートを使うのが推奨されています。
「HTMLはダブル、CSSはシングル」と覚えておくと迷いません。

```css
/* CSSの中はシングルクォート */
body {
  font-family: 'Noto Sans JP', sans-serif;
}
```

## 画像にはaltをつける

img要素には必ずalt属性をつけます。目の不自由な方が使う音声読み上げソフトが、
画像の代わりに読み上げる文章になるからです。プロフィール画像なら内容が伝わる言葉を入れます。
見た目だけの飾り画像であれば、あえて空にしてalt=""としてもかまいません。

```html
<img src="avatar.jpg" alt="鈴木太郎さんのプロフィール写真">
```

## 見た目ではなく意味でタグを選ぶ

「クリックできるからdivにonclickをつける」のような書き方ではなく、リンクにはaタグ、
見出しにはh1からh6、段落にはpタグというように、要素が本来持つ意味に沿って選びます。
読み上げ機能やSEO、後からのメンテナンスがしやすくなります。

```html
<!-- 避けたい例：見た目だけ整えたdiv -->
<div class="link-like" onclick="location.href='/profile'">プロフィールへ</div>

<!-- 良い例：本来リンクの役割を持つaタグを使う -->
<a href="/profile">プロフィールへ</a>
```

## HTMLとCSSの役割を分けておく

style="color: red;"のようにHTMLタグの中に直接スタイルを書き込む（インラインスタイル）のは避けて、
見た目の指定はできるだけCSSファイルにまとめます。HTMLは構造、CSSは見た目と役割を分けておくと、
後でデザインを変えたいときにHTMLを触らずに済みます。

```html
<!-- 避けたい例 -->
<p style="color: gray; font-size: 14px;">自己紹介文です。</p>
```

```css
/* 良い例：style.cssなど別ファイルにまとめる */
.profile-text {
  color: gray;
  font-size: 14px;
}
```

## インデントは半角スペース2つ、タブは使わない

コードの入れ子を表すインデントは、半角スペース2つに統一します。
タブキーを使うと人によって見た目の幅が変わってしまうことがあるためです。
エディタの設定でタブキーを押すとスペース2つに変換されるようにしておくと楽です。

```html
<div class="profile">
  <img src="avatar.jpg" alt="プロフィール写真">
  <p>自己紹介文です。</p>
</div>
```

## 行末の余分な空白を残さない・文字コードはUTF-8

行の最後にスペースが残っていると、Gitで差分を見たときに変更箇所が分かりにくくなります。
保存前にエディタの機能で行末の空白を削除しておくと安心です。
文字コードはUTF-8（BOMなし）にして、head内にmeta charsetでutf-8を指定します。

```html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="utf-8">
  <title>自己紹介ページ</title>
</head>
```

## CSSはコロンの後ろにスペース、最後にセミコロン

プロパティと値の間（コロンの後ろ）に半角スペースを1つ入れ、コロンの前にはスペースを入れません。
宣言の最後には必ずセミコロンをつけます。1つしか書かない場合でも省略しないのがポイントです。

```css
/* 避けたい例 */
.card{
  color:#333;
  padding:16px
}

/* 良い例 */
.card {
  color: #333;
  padding: 16px;
}
```

## セレクタごとに改行、ルールとルールの間は空行

カンマ区切りで複数のセレクタを書くときは、1つずつ改行します。
別々のCSSルール同士の間には空行を1行入れておくと、どこからどこまでが1つの塊か一目で分かります。

```css
h1,
h2,
h3 {
  font-weight: normal;
}

.profile {
  display: flex;
  align-items: center;
}
```

## クラス名は「役割」が分かる名前にする

クラス名は見た目ではなく、そこに何が入っているか・どういう役割かを表す名前にします。
単語同士はハイフンでつなぎます（キャメルケースやアンダースコアではなく）。

```css
/* 避けたい例：見た目そのままの名前、単語のつなぎ方もバラバラ */
.text_gray14 {}
.bigImage {}

/* 良い例：役割が伝わる名前、ハイフンつなぎ */
.profile-text {}
.hero-image {}
```

## 0には単位をつけない・1未満の小数は先頭の0を省く

marginやpaddingが0のときは、0pxや0emではなく単に0とだけ書きます。
また、0.5emのような1未満の小数は、先頭の0を省いて.5emと書くのが慣習です。
どちらも意味は変わらず、少しだけコードがすっきりします。

```css
/* 避けたい例 */
margin: 0px;
opacity: 0.8;

/* 良い例 */
margin: 0;
opacity: .8;
```

## まとめ

以上が、今回のような小規模な模写コーディング課題で押さえておくと安心な基本ルールです。
逆に、TODOコメントの書式やタグの省略記法、プロパティのアルファベット順並び替えといった細かい部分は、
大人数のプロジェクトでの一貫性を保つための工夫なので、1人で作る今回の課題では気にしすぎなくて大丈夫です。
まずは課題ページの仕様（幅960px、ブレークポイント600pxなど）を再現しながら、
上記のポイントをひとつずつ意識してコードを書いてみましょう。
